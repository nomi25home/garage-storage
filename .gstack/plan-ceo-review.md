## Vision

### 10x Check
Today Kapaat is a single-user SQLite inventory app with a documented-but-unimplemented sync conflict strategy. In 12 months it should be a **multi-user inventory system with durable, auditable data** — where every mutation is traceable, concurrent edits don't silently lose data, and Sheets sync can't stomp local edits. This plan moves from "v1.1.0 shipped, P2 items partially done" toward that future by hardening the two active roadmap items and laying the foundations multi-user needs, without the Postgres rewrite.

## Accepted Scope (added to this plan)
- `/api/sync-row` honors incoming `item_id`: skip if item exists, insert otherwise
- Migration registry: versioned migration functions, no raw `ALTER TABLE` outside the registry
- `audit_log` table + write path hook on every create/update/delete (requires user identity from auth)
- Optimistic locking on item edits (`version` column, `WHERE version = ?`)
- `POST /api/backup/retention` + auto-prune on backup download
- Dashboard banner when a sync conflict is detected
- Authentik OIDC login with scopes, user identity in requests, per-user isolation
